# v0.5 batch — everything except Windows

User decision (2026-06-11): do the full backlog except Windows support. Waves are
SERIALIZED (one implementer at a time — shared working tree), each verified before the next.

## Wave 1 — quick wins
- **W1a (CI)**: macOS universal build — replace the two macOS matrix legs with one
  `--target universal-apple-darwin` leg. Kills the `latest.json` delete-asset race between the
  two mac jobs. Tauri v2 updater falls back to `darwin-universal` when `{target}-{arch}` is
  absent — VERIFY on the next release that latest.json carries the universal entry and an
  installed app still updates.
- **W1b (Rust+FE)**: fix `config_set_option_enabled` addressing — keyword-only lookup re-enables
  the wrong line when a host has an enabled+disabled pair of the same keyword. Address by
  occurrence index (or line id) end-to-end (edit.rs op → command → useSetOptionEnabled →
  DisabledOptionRow).
- **W1c (FE)**: drag-reorder hosts in the sidebar — backend `config_reorder_hosts` already
  exists, UI never wired. Within-file reordering only (single-file scope and per-group in All
  view). HTML drag events or pointer-based; persist via the existing mutation.

## Wave 2 — key management (the v0.5 headline)
Keys dialog (toolbar, KeyRound icon), consistent with Discover/History:
- Rust `keys.rs`: scan `~/.ssh` for keypairs (id_*, *.pub matching), fingerprints via
  `ssh-keygen -lf` (argv only), agent status via `ssh-add -l`, generate ed25519 via
  `ssh-keygen -t ed25519 -f <path> -N ""` (no-passphrase inline with explicit warning;
  passphrase flow = launch interactive `ssh-keygen` in the user's terminal via the existing
  launcher), read pubkey for copy.
- Deploy: `ssh-copy-id -i <pub> <alias>` launched IN THE TERMINAL (interactive password),
  reusing connect::build_launch's per-terminal plumbing with a parametrized command.
  SECURITY: argv vectors only; alias validated by the existing validate_alias; key paths must
  resolve inside ~/.ssh.
- UI: key list (name, type, bits, fingerprint mono, "in agent" dot), copy-pubkey button,
  generate form, per-key "Deploy to host…" (host picker → terminal).

## Wave 3 — known_hosts editor
- Rust: list entries (host token, key type, SHA256 fingerprint), delete by host via
  `ssh-keygen -R <host> -f <file>` (argv; it backs up to .old itself), hashed-entry awareness
  (show as "hashed"). Path: default known_hosts; reuse discover.rs parsing where possible.
- UI: toolbar dialog (ShieldX icon): search, entry rows, delete w/ AlertDialog confirm.

## Wave 4 — host organization + per-host terminal + raw view
- **Move host between files**: `config_move_host(alias, target_file)` — move the Host block's
  raw lines verbatim (lossless), persist BOTH files (backup + drift guard each). UI in the
  editor's ⋯ menu ("Move to file ▸") and optional drag-to-group later.
- **Duplicate host**: `config_duplicate_host(alias, new_alias)` — copy block, rewrite Host line.
  UI in ⋯ menu.
- **Per-host terminal override**: stored app-side in settings (`hostTerminalOverrides:
  Record<alias, terminalId>`), NOT in the config file. Resolution: host override > global
  terminalId > default. UI: small dropdown on the editor Connect button (split-button menu).
- **Raw file view**: `config_read_file(path)` (path must be a managed file → else ForbiddenPath);
  read-only dialog with mono <pre> + copy, opened from the sidebar group header context/title
  area and the file-scope picker.

## Wave 5 — small batch
- Launch at login: `tauri-plugin-autostart` + Settings → General toggle.
- Global hotkey: `tauri-plugin-global-shortcut`, fixed ⌥⌘K = show window + open palette,
